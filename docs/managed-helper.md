# Experimental managed Swift helper

Status: implementation compiled only. QA, tests, runtime probes, reviews, actual
TUI/provider sessions and G0 are NOT RUN at the user's request. No production
compatibility or release readiness claim is made.

## Build and CLI

Manifest owner must add `.executableTarget(name: "CodexHubHelper")` and
`.executable(name: "codex-hub", targets: ["CodexHubHelper"])`. No package
dependencies: Apple Foundation, Darwin, CoreFoundation and CryptoKit only.

Compile without changing the shared manifest:

```sh
swiftc -swift-version 6 -O -o /tmp/codex-hub-s4 Sources/CodexHubHelper/LocalIO.swift Sources/CodexHubHelper/Observation.swift Sources/CodexHubHelper/main.swift
```

Commands (examples, not executed during implementation):

```sh
codex-hub help
codex-hub doctor --codex /absolute/path/to/codex
codex-hub run --experimental --codex /absolute/path/to/codex
```

`--codex` is optional (PATH lookup). Only investigated `codex-cli 0.163.0` is
accepted. Doctor runs a bounded version query, not an app-server session. Run
requires explicit experimental opt-in. All additional CLI options, positional
prompts, profiles, resume/fork commands and overrides are rejected because their
routing has not been established. Existing environment/cwd and Codex's own
configuration/authentication remain in effect. No aliases or config are edited.

The launcher starts a detached helper and then `execv`s the actual Codex TUI with
`--remote unix://<private runtime>/relay.sock`, preserving its terminal and PID.
The helper owns one app-server (`app-server --listen unix://.../server.sock`).
It does not depend on UI lifetime. TERM/INT/HUP or loss of the original TUI
parent shuts down the owned sockets and terminates only the owned server child.
The helper starts with closed extraneous descriptors and no controlling terminal. It accepts one same-user TUI connection and
connects once to the same-user upstream. No reconnection, initialize request,
approval response, prompt or automatic replay is generated by Hub.

## Producer contract: schema version 1

Persistent root:

`~/Library/Application Support/CodexHub/managed-runs/<homeHash>/sessions/<runUUID>/<localFileUUID>.jsonl`

- Effective home: environment `CODEX_HOME`, else `NSHomeDirectory() + "/.codex"`.
- Canonical home: `URL(fileURLWithPath: effectiveHome).resolvingSymlinksInPath().standardizedFileURL.path`.
- homeHash: lowercase SHA256 hex of canonical home UTF-8. This is grouping
  identity, not a permission or ownership check.
- One generated local filename per actual thread, not a filename derived from
  untrusted thread data. Thread IDs are never replaced with Hub run IDs.
- Directories from CodexHub down: same user, 0700, opened component by component
  without following symlinks. Files: exclusive creation, 0600, no symlinks.
- Outside the app's `homes/<hash>` database so clearing that metadata cannot
  unlink a live producer. Producer files have a 16 MiB per-run observation bound;
  cumulative disk retention across runs must be handled separately by the app.

Every thread record has these envelope fields:

| Field | Type / meaning |
|---|---|
| hub_schema_version | integer `1` |
| hub_source | literal `direct-relay` |
| codex_home_id | homeHash |
| run_id | Hub UUID |
| thread_id | actual server thread ID |
| timestamp | local ISO8601 receive wall time |
| received_monotonic_ns | decimal string, local uptime nanoseconds |
| type | `session_meta` or `event_msg` |
| payload | allowlisted shape below |

First record: `type=session_meta`, `payload={id:<thread ID>, processes:{tui:{pid,start_seconds,start_microseconds},app_server:{...},relay:{...}}`.
Process start values are OS `proc_pidinfo(PROC_PIDTBSDINFO)` values, measured
while the owned processes exist. TUI identity is the launcher identity preserved
by exec, not guessed from cwd. No raw command line or environment is persisted.

All subsequent records use `type=event_msg`. Exact payload shapes:

| payload.type | Other fields |
|---|---|
| task_started | `turn_id`: actual ID; optional `status`: `inProgress`, `completed`, `interrupted`, `failed` |
| task_complete | `turn_id`: actual ID; optional `status`: same enum |
| token_count | `turn_id`: actual ID; `info.total_token_usage`: nonnegative integer `input_tokens`, `cached_input_tokens`, `output_tokens`, `reasoning_output_tokens`, `total_tokens`; optional `cache_write_input_tokens` |
| hub_tool_started | `turn_id`, `item_id`, `tool_kind` |
| hub_tool_completed | `turn_id`, `item_id`, `tool_kind` |
| hub_approval_requested | `turn_id`, `request_id`: original integer or identifier string |
| hub_approval_resolved | `request_id`: original integer or identifier string; turn ID intentionally absent because installed notification lacks it |
| measurement_gap | `reason`: enum below; no fabricated turn ID |
| hub_connection | `state`: `disconnected`; no fabricated turn ID |

`tool_kind`: `commandExecution`, `fileChange`, `mcpToolCall`, `dynamicToolCall`,
`collabAgentToolCall`, `webSearch`, `imageGeneration` only. Approval observation
covers installed `item/commandExecution/requestApproval`,
`item/fileChange/requestApproval`, `item/permissions/requestApproval`; only
`serverRequest/resolved` clears a request. Other requests pass through unchanged
but are not classified as approvals.

Gap reasons: `observer_queue_overflow`, `frame_bound`, `upgrade_bound`,
`unsupported_upgrade`, `unsupported_frame`, `unsupported_message`, `invalid_json`,
`invalid_identifier`, `invalid_usage`, `metadata_bound`, `thread_bound`,
`metadata_unavailable`, `connection_closed`.

`run-events.jsonl` in the same run directory is a run-level diagnostic stream;
it has the same envelope without `thread_id`, no session_meta, and carries gaps
and disconnected lifecycle even when no thread was observed. It must not create
a fake session. Gaps are also copied to each already-known thread file. At
shutdown lifecycle delivery is best effort with a one-second drain limit; disk
failure cannot guarantee a persisted gap. Consumers must also treat stale/crashed
sources as unknown/disconnected, never infer Idle from absent records.

Example (synthetic identifiers):

```json
{"hub_schema_version":1,"hub_source":"direct-relay","codex_home_id":"<homeHash>","run_id":"<runUUID>","thread_id":"thread-1","timestamp":"2026-10-17T09:00:00Z","received_monotonic_ns":"1000000000","type":"event_msg","payload":{"type":"token_count","turn_id":"turn-1","info":{"total_token_usage":{"input_tokens":20,"cached_input_tokens":0,"output_tokens":10,"reasoning_output_tokens":2,"total_tokens":30}}}}
```

## Consumer requirements

Use `managed-runs/<homeHash>` as the reader's separate home-like root (it contains
`sessions/`). Preserve `codex_home_id` as real home identity; the synthetic reader
root is not a different Codex account/session. Reject unknown schema versions.
Select one authoritative source per real home/thread/counter epoch and reconcile
against original rollout counters before switching. Never add direct and rollout
usage. Only cumulative `total` is emitted, never `last` or legacy token_count
notifications from the server. First snapshot remains a baseline, not new work.
Reasoning is a subset of output. Child inclusion is unverified: keep scope Partial.

Maintain tool and approval ID sets; match request IDs without coercing strings
to integers. `hub_approval_resolved` clears only that request. Gap invalidates
throughput/baselines and connected activity certainty; reconciling source/epoch
is the consumer's responsibility. This producer stops observation after a gap
instead of attempting unsafe frame resynchronization. A task completion, not
socket closure, establishes completed activity. Final usage may arrive after
completion and must not reactivate a turn.

## Relay and observation boundaries

Two blocking socket pumps forward exactly the received bytes, including HTTP
Upgrade, WebSocket control frames, unknown methods/fields/IDs, initialize opt-outs
and client responses. Partial writes and EINTR are handled; a hard transport
failure closes both halves rather than fabricating protocol responses.

Only server bytes are copied to a serial observer after forwarding. The queue is
bounded at 32 chunks of 32 KiB; individual frames/messages at 1 MiB; HTTP headers
at 16 KiB; threads at 256. Fragmented text messages are supported. Binary,
compressed, masked server frames and unrecognized framing stop observation with
a gap; they are still forwarded. No app-server request is sent by the observer.
Raw text exists transiently only inside bounded transport/parser buffers and is
never persisted. Supported agent-message text is accumulated only in bounded
memory for the [Live estimator](live-estimator.md), then discarded. Unsupported
model/provider mappings remain unavailable; runtime parity has not been tested.

The [optional Hook installer and recorder](optional-hooks.md) require explicit
user consent and manual Codex `/hooks` trust. No installation or trust change
was performed during implementation.
